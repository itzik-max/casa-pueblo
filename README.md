# CASA | הבית שלי — פורטל לקוחות קאסה פואבלו

אב-טיפוס להצגה, לפי מסמך האפיון גרסה 1.0. כל המסכים עובדים עם נתוני דמו של משפחה אחת (בית אברהמי). אין עדיין שרת או מסד נתונים.

## איך פותחים

- פותחים את `index.html` בדפדפן (לחיצה כפולה). לא צריך התקנה.
- **כניסה כלקוח:** הכפתור "כניסה כלקוח" במסך הכניסה, או `index.html?as=client`
- **כניסה כצוות (Back Office):** הכפתור "כניסה כצוות", או `index.html?as=staff`
- **אזור הלקוח עם תפריט צד** במקום טאבים: `index.html?as=client&nav=side`. אפשר גם לעבור בין התצוגות בכפתור שבהדר.
- השינויים שעושים בהדגמה (אישורים, הוצאות, תמונות) נשמרים בדפדפן.
  - הכפתור "איפוס נתוני ההדגמה" בתפריט מחזיר את הכול להתחלה.

## המערכת האמיתית (Supabase)

הקוד מוכן, ומחכה לפרויקט Supabase. כל עוד `js/config.js` ריק, האתר עובד במצב הדגמה בלבד, כמו קודם.

**איך זה בנוי:**
- **פרויקט = מסמך אחד:** כל משפחה היא שורה ב־`projects`, וכל הנתונים שלה ב־`data` (JSON), באותו מבנה של נתוני הדמו. כך כל המסכים עובדים בלי שינוי.
- **כניסה:** מייל בלבד, עם קישור כניסה (בלי סיסמה).
  - מי שהמייל שלו ב־`staff_emails` מקבל הרשאת צוות.
  - בן משפחה מצורף לפרויקט דרך `invites`, כשהוא נכנס בפעם הראשונה.
- **הרשאות (RLS):**
  - צוות רואה ועורך הכול.
  - לקוח רואה רק את הפרויקט שלו, ושומר רק דרך `save_project`. הפונקציה חוסמת אותו מלשנות פרטי פרויקט, צוות, לוח זמנים, עדכונים ובעלי מקצוע.
- **שמירה:** עם מספר גרסה. אם שניים שומרים באותו רגע, השני מקבל הודעה, והגרסה העדכנית נטענת.
- **קבצים:** bucket פרטי `files`, בתיקייה `<project_id>/`. קבצים בתיקייה `internal/` גלויים רק לצוות.
  - בנתונים הקובץ נשמר כ־`f:<נתיב>`, ונפתח דרך קישור חתום ל־12 שעות (`media()` ו־`openFile()` ב־`js/live.js`).
  - תמונות מהנייד מוקטנות ל־2000px לפני ההעלאה.
- **יומן:** `audit_log` נכתב בצד השרת בכל שמירה, עם מי שמר ואילו חלקים השתנו.

**מה ג'ורג' והצוות עושים:**
1. **פרויקט חדש:** ב־Back Office → "פרויקט חדש". ממלאים שם, משפחה, מיילים של הלקוחות ותמונה. המשפחה מקבלת קישור כניסה במייל.
2. **בתוך הפרויקט:** הפעולות ב־Back Office מעדכנות את המסד ישירות: עדכון שבועי, שלב, לוח זמנים, תכניות וגרסאות (עם הקובץ), תמונות, מסמכים, תשלומים, שינויים, בעלי מקצוע ומשתמשים.
3. **המשפחה:** מאשרת תכניות ושינויים, בוחרת חומרים, מעלה מסמכים וקבלות, ופותחת פניות שירות.

**הפעלה, פעם אחת:**
1. פותחים פרויקט Supabase ושומרים ב־`~/.claude/settings.json` את `CASA_SUPABASE_REF`, `CASA_SUPABASE_DB_PASSWORD`, `CASA_SUPABASE_URL` ו־`CASA_SUPABASE_PUBLISHABLE_KEY`.
2. מריצים את המיגרציה: `cd scripts && npm install`, ואז `node scripts/pgq.js supabase/migrations/20261029000000_init.sql`.
3. מוסיפים את מיילי הצוות: `insert into staff_emails (email, name) values ('...', '...');`
4. ממלאים את `js/config.js` בכתובת ובמפתח ה־publishable, ומעלים.
5. ב־Authentication → URL Configuration מגדירים את כתובת האתר.

**ניהול משתמשים:**
- **צוות:** ב־Back Office, במסך "הרשאות". מוסיפים שם ומייל, והאדם מקבל קישור כניסה. הסרה חוסמת אותו מיד. אי אפשר להסיר את עצמך.
- **משפחה:** בכל פרויקט, בכרטיס "משתמשים בפרויקט". רואים מי הוזמן ומי כבר נכנס, ואפשר לשלוח קישור שוב או להסיר.

**הסיכום השבועי:**
- **איפה עורכים:** ב־Back Office, במסך "סיכום שבועי" (`js/weekly.js`). יש בו שתי רשימות: "מה עשינו השבוע" ו"מה הלאה". הכפתור "מילוי אוטומטי" בונה טיוטה מהעדכונים, מהשלבים, מהתכניות ומהאישורים של השבוע.
- **יום שישי, 15:00:** הפונקציה `weekly` יוצרת טיוטה לכל פרויקט שאין לו, ושולחת מייל לאישור לכתובות שב־`app_settings.approver_emails` (חורחה).
- **יום שישי, 17:00:** כל סיכום שאושר עולה לבית של המשפחה, נוספת התראה, ונשלח מייל לכל מי שהוזמן לפרויקט. סיכום שלא אושר לא נשלח, וחורחה מקבל על כך הודעה.
- **"שליחה עכשיו":** שולח מיד את הסיכום של הפרויקט הפתוח.
- **התשתית:**
  - התזמון: `pg_cron` ו־`pg_net` (`supabase/migrations/20261029010000_weekly_cron.sql`). הפונקציה בודקת את השעה בישראל, ולכן התזמון נכון גם בשעון קיץ וגם בשעון חורף.
  - המיילים יוצאים דרך Resend.
  - סודות הפונקציה: `RESEND_API_KEY`, `MAIL_FROM`, `SITE_URL`, `CRON_SECRET`.
  - ב־Vault: `weekly_url` ו־`cron_secret`.
- **ההרשאות:** הלקוח לא יכול לשנות סיכומים, כי `weeklySummaries` מוגן ב־`save_project`.

**תכניות:**
- **קטגוריות:** הקבועות הן כתב כמויות, הריסה, בניה, העמדה, חשמל, אינסטלציה, הנמכות תקרה, ריהוט, אלומיניום ומסגרות. חורחה יכול להוסיף קטגוריות, והן נשמרות ב־`planCategories` של הפרויקט.
- **סטטוס ביצוע:** "מאושר לביצוע" או "טיוטה" (`plan.exec`). רק חורחה משנה אותו: `staff_emails.admin` → `profiles.is_admin`, ונאכף גם ב־`save_project`. גרסה חדשה חוזרת להיות טיוטה.
- **הרשימה:** התכניות המאושרות למעלה, בירוק. מתחתן הגרסאות הקודמות.

**שיתוף קבצים:**
- בכל קובץ (תכנית, מסמך, חשבונית, הזמנה) יש כפתורי "וואטסאפ" ו"מייל" (`shareButtons` ו־`bindShare` ב־`js/todo.js`).
- **וואטסאפ:** בטלפון הקובץ עצמו מצורף דרך תפריט השיתוף. במחשב נשלח קישור הורדה.
- **מייל:** הקובץ נשלח כקובץ מצורף דרך הפונקציה `send-file`, שבודקת שלשולח מותר לראות את הקובץ.

**חומרים:** לכל פריט יש איש קשר (שם וטלפון), הזמנה וחשבונית. הקבצים נכנסים גם ל"מסמכים". גם הלקוחות יכולים להוסיף פריטים ולערוך אותם.

**המטלות שלי:** רשימת המטלות של המשפחה (מטלה, תיאור, אחריות, דד ליין). כל מטלה אפשר להוסיף ליומן Google או להוריד כקובץ ‎.ics (אייפון ו־Outlook), עם תזכורת יום לפני. חיבור קבוע ליומן, שמתעדכן לבד, עוד לא נבנה.

**תמונות:**
- כל עדכון יכול להשתייך לכמה שלבי בנייה (`stages`).
- יש שתי תצוגות: "הכל", ו"ציר לפי שלבים". בציר, תמונה עם כמה שלבים מופיעה בכל אחד מהם.

**לוח זמנים:** שלוש תצוגות לבחירה: גאנט, מסלול ולפי חודשים.

**אחריות:**
- רק על מוצרים שנרכשו (שדה "אחריות עד" בחומרים). על עבודות של קאסה פואבלו לא מוצגת אחריות.
- 90 יום לפני הסוף הפונקציה `reminders` שולחת מייל והתראה, פעם אחת לכל מוצר.

**לפני שמשתמשים עם לקוחות אמיתיים:**
- **SMTP משלהם:** שירות המייל המובנה של Supabase מוגבל לכמה מיילים בשעה.
- **תבניות מייל בעברית:** מדביקים את `supabase/templates/magic_link.html` ב־Authentication → Email Templates, גם ב־Magic Link וגם ב־Confirm signup.
- **כתובת קבועה:** עדיף כתובת משלהם במקום github.io, ומאגר פרטי.

**עוד לא נבנה:**
- כניסה ב־SMS.
- התראות במייל ובוואטסאפ.
- טבלאות נפרדות לכל תחום. כרגע הכול במסמך אחד, וזה מספיק לעשרות פרויקטים.
- OCR לחשבוניות.
